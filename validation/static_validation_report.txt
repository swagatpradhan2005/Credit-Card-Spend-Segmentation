PART 2 -- PIPELINE STATIC REVIEW (code-level, not executed)
======================================================================

[REVIEWED] 00_project_config.py defines every catalog/schema/volume/table
    name and path exactly once; 01-06 reference these variables only
    (verified: no repeated/hardcoded path or table name outside this file).

[REVIEWED] 01_setup_databricks.py uses CREATE CATALOG/SCHEMA/VOLUME
    IF NOT EXISTS and dbutils.fs.mkdirs (both idempotent).

[REVIEWED] 02_bronze_ingestion.py reads all columns as STRING, sets
    ignoreLeadingWhiteSpace/ignoreTrailingWhiteSpace to false, and asserts
    row counts of 2,000 and 121,900 before proceeding.

[REVIEWED] 03_silver_transformation.py uses try_cast (not cast) for the
    amount conversion; the dedupe/orphan/invalid-amount rejections use
    disjoint row sets, so the documented transition arithmetic
    (121,900 -> 120,400 -> 120,000 -> 119,200) is internally consistent;
    spend is defined once as the signed sum of amount with no ABS() call
    anywhere in the file.

[REVIEWED] 04_gold_transformation.py computes dominance with
    ROW_NUMBER() OVER (PARTITION BY customer_id, month ORDER BY spend
    DESC, merchant_category ASC) -- not GROUP BY MAX(spend) joined back
    to detail -- so a spend tie cannot produce two dominant rows or grow
    the table past 48,000.

[REVIEWED] 05_validation.py checks every count in EXPECTED_RESULTS.md and
    raises (does not just print) on any failure, so 06_export_gold.py
    cannot silently run after a failed validation if the job JSON's
    dependency chain is respected.

[REVIEWED] 06_export_gold.py asserts the Gold row count before writing,
    coalesces to a single part file, and asserts exactly one file exists
    in the export folder afterward.

[REVIEWED] snowflake/01-03.sql: no embedded credentials; COPY INTO in
    02_snowflake_load.sql does not pass FORCE = TRUE, so Snowflake's load
    metadata makes a second run against the same file a zero-row no-op;
    03_required_snowflake_questions.sql uses QUALIFY ROW_NUMBER() for
    dominance (Q2) and AVG(spend_share) rather than
    SUM(spend)/SUM(customer_month_spend) for the per-customer share (Q1).
